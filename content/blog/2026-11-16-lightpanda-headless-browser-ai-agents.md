> **TL;DR** — Lightpanda는 Chromium 포크가 아닌, Zig로 처음부터 새로 작성한 헤드리스 브라우저입니다. 2026년 10월 1.0.0 정식 출시와 함께 CDP·WebDriver·MCP 세 가지 웹 자동화 프로토콜을 모두 기본 지원하는 첫 번째 브라우저가 됐습니다. 그래픽 렌더링은 의도적으로 제외했고, Playwright·Puppeteer·Selenium과 그대로 연동됩니다. 라이선스는 AGPL-3.0-only입니다.

---

## 왜 Chromium을 그냥 쓰지 않는가

헤드리스 브라우저 자동화를 구현할 때 가장 먼저 떠오르는 선택지는 Chromium입니다. Playwright와 Puppeteer가 이미 탄탄한 생태계를 갖추고 있고, Chrome DevTools Protocol(CDP)은 사실상 표준이 됐습니다. 그런데 왜 누군가 처음부터 브라우저를 다시 만들었을까요?

Chromium은 근본적으로 사람이 쓰는 데스크톱 브라우저입니다. 헤드리스 모드는 GUI 렌더링 엔진을 끄는 방식으로 구현되어 있어서, 화면에 그릴 필요가 없는 작업에도 렌더링 파이프라인 관련 코드와 메모리가 적재됩니다. AI 에이전트·크롤러·데이터 추출 파이프라인처럼 DOM 조작과 JavaScript 실행이 핵심이고 픽셀 출력은 필요 없는 워크로드에서는 불필요한 오버헤드입니다.

[Lightpanda](https://github.com/lightpanda-io/browser)는 이 전제 자체를 바꿨습니다. 처음부터 헤드리스, 처음부터 자동화를 목적으로 설계하고, 그래픽 렌더링 엔진은 아예 포함하지 않았습니다.

---

## 무엇이 다른가: 확인된 사실

### 언어와 아키텍처

Lightpanda는 [Zig](https://ziglang.org/)로 작성됐습니다. Chromium(C++)이나 WebKit(C++)의 포크가 아니며, 기존 브라우저 엔진을 감싼 래퍼도 아닙니다. JavaScript 엔진은 V8을 사용하므로 웹 표준 JS 호환성은 유지하면서도, 렌더링에 필요한 나머지 레이어는 최소한으로 구현했습니다.

### 세 가지 프로토콜 동시 지원

[1.0.0 릴리스 노트](https://github.com/lightpanda-io/browser/releases/tag/1.0.0)와 [공식 블로그](https://lightpanda.io/blog/posts/lightpanda-1-0)에 따르면, Lightpanda 1.0은 WebDriver 지원을 추가하면서 **CDP·WebDriver·MCP** 세 가지 웹 자동화 프로토콜을 모두 기본 지원하는 유일한 브라우저가 됐습니다.

- **CDP**: Playwright, Puppeteer, ChromeDP 등 기존 도구와 그대로 연동
- **WebDriver**: Selenium 연동 가능
- **MCP**: 별도 브리지 없이 LLM·에이전트 프레임워크가 직접 도구 호출로 브라우저를 제어

### 서브커맨드 구조

1.0.0 기준 다섯 가지 서브커맨드가 존재합니다([README](https://github.com/lightpanda-io/browser/blob/main/README.md) 기준):

| 서브커맨드 | 역할 |
|---|---|
| `fetch` | URL 로드 후 결과 덤프 |
| `serve` | CDP/BiDi 서버 실행 |
| `mcp` | stdio 또는 HTTP 방식의 MCP 서버 실행 |
| `agent` | LLM 기반 브라우징 REPL |
| `run` | 저장된 세션 스크립트를 LLM 없이 재실행 |

`agent`와 `run`의 조합이 흥미롭습니다. 에이전트가 웹을 탐색한 세션을 JavaScript로 저장하고, 이후에는 LLM 없이 `run`으로 반복 실행할 수 있습니다. 비용 최적화가 필요한 고빈도 크롤링에서 유용한 패턴입니다.

### Web Platform Tests 통과 수

[공식 블로그](https://lightpanda.io/blog/posts/lightpanda-1-0)에 따르면 2024년 11월 시점의 2,645개에서 1.0.0 기준 **1,739,845개**의 Web Platform Tests 서브테스트를 통과했습니다. 다만 아직 통과하지 못한 테스트의 상당 부분은 CSS, SVG, 그래픽 렌더링 관련 항목으로, Lightpanda가 의도적으로 지원하지 않는 영역입니다. 개발팀은 Shadow DOM, IndexedDB, WebSocket, 웹 워커, 폼 처리 등 **프로그래밍 방식의 DOM 조작** 기능에 집중하고 있습니다.

## 설치: 세 가지 경로

### Homebrew (macOS / Linux, nightly 빌드)

```bash
brew install lightpanda-io/tap/lightpanda
```

Homebrew 경로는 nightly 빌드를 추적합니다. 안정 버전이 필요하다면 아래 방법을 사용하세요.

### GitHub Releases (특정 버전)

```bash
curl -L -o lightpanda \
  https://github.com/lightpanda-io/browser/releases/download/1.0.0/lightpanda-x86_64-linux
chmod +x lightpanda
```

### Docker (Linux amd64 / arm64)

```bash
docker run -d --name lightpanda -p 9222:9222 lightpanda/browser:nightly
```

CDP 클라이언트는 `localhost:9222`로 연결하면 Playwright·Puppeteer가 Chrome DevTools Protocol을 통해 그대로 작동합니다.

---

## MCP 서버 내장: 에이전트 연동 예시

내장 MCP 서버는 AI 에이전트 프레임워크가 중간 CDP 브리지 없이 구조화된 도구 호출로 브라우저를 제어할 수 있게 합니다. stdio 방식으로 실행하면:

```bash
lightpanda mcp
```

HTTP 방식으로 실행할 수도 있습니다. Claude Desktop이나 MCP를 지원하는 에이전트 프레임워크에서 이 엔드포인트를 MCP 서버로 등록하면 별도 Playwright 코드 작성 없이 에이전트가 브라우저를 직접 조작할 수 있습니다.

---

## browser-use와 무엇이 다른가

moonyth.app에서 이전에 다룬 `browser-use`(Python 라이브러리)와 계층이 다릅니다.

- **browser-use**: LLM이 무엇을 클릭하고 입력할지 결정하는 **오케스트레이션 계층**. Chromium 위에서 작동.
- **Lightpanda**: Chromium 자체를 경량 런타임으로 교체하는 **런타임 계층**. 에이전트 프레임워크에 무관하게 동작.

두 도구는 상호 배타적이지 않습니다. `browser-use`의 백엔드 브라우저를 Lightpanda로 교체하는 조합도 이론적으로 가능합니다.

## 주의해야 할 제한 사항

**스크린샷·PDF·실제 렌더링 불가**: Lightpanda는 페이지 렌더링, 스크린샷 촬영, PDF 생성을 지원하지 않습니다. 비주얼 회귀 테스트나 PDF 생성이 필요한 팀은 여전히 풀 브라우저가 필요합니다.

**라이선스**: [LICENSING.md](https://github.com/lightpanda-io/browser/blob/main/LICENSING.md)에 따르면 기본 라이선스는 **AGPL-3.0-only**입니다. Lightpanda를 수정해 네트워크 서비스로 제공하는 경우 수정본을 같은 조건으로 공개해야 합니다. 상용 조건은 별도로 명시되어 있지 않습니다.

**플랫폼**: Linux 바이너리는 glibc 의존성이 있어 musl 기반 시스템(일부 Alpine Docker 이미지 등)에서는 동작하지 않을 수 있습니다. Windows는 WSL2를 통해서만 지원됩니다.

**성능 수치 맥락**: 공식 사이트와 블로그에 헤드리스 Chrome 대비 최대 4.4배 빠르고 7배 적은 메모리를 사용한다는 수치가 제시되어 있으나, 이는 Lightpanda 자체 측정 기준이며 독립적인 제3자 검증은 확인되지 않았습니다. 실제 워크로드에서는 별도 벤치마킹이 필요합니다.

## 정리

Lightpanda는 "헤드리스 브라우저 = Chromium을 화면 없이 띄우는 것"이라는 가정을 근본부터 다시 쓴 프로젝트입니다. AI 에이전트·크롤러·DOM 추출 파이프라인처럼 렌더링이 필요 없고 처리량이 중요한 워크로드에서 고려해볼 만한 대안입니다. 다만 AGPL-3.0 라이선스, 렌더링 불가, 플랫폼 제약은 도입 전에 반드시 팀 내에서 검토해야 할 항목입니다.
