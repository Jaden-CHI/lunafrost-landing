> 2026-11-07 누락분을 2026-11-14에 보완 발행한 글입니다.

> **TL;DR** — Dify는 챗봇·RAG 파이프라인·AI 에이전트를 비주얼 노드 에디터로 엮는 오픈소스(Apache 2.0) LLM 앱 플랫폼이다. Docker Compose 세 줄로 셀프호스트 서버를 띄울 수 있고, 외부 LLM API 의존 없이 Ollama로 로컬 추론까지 붙일 수 있다. 이 글은 [공식 GitHub](https://github.com/langgenius/dify)와 [공식 문서(docs.dify.ai)](https://docs.dify.ai/en/self-host/deploy/quick-start/docker-compose)를 1차 출처로 작성했다.

---

## 왜 Dify인가

LLM 앱을 직접 구축할 때 흔히 맞닥뜨리는 벽이 있다. API 키 관리, 프롬프트 버전 관리, 문서 임베딩 파이프라인, 에이전트 오케스트레이션—각각 별도 서비스를 연결하다 보면 운영 복잡도가 선형이 아닌 지수로 늘어난다. Dify는 이 모든 조각을 하나의 플랫폼으로 묶는다.

[공식 GitHub 저장소](https://github.com/langgenius/dify)에 따르면 Dify는 오픈소스 LLM 애플리케이션 개발 플랫폼으로, 챗봇·RAG 파이프라인·AI 에이전트를 비주얼 워크플로 에디터로 구축할 수 있으며 셀프호스트와 클라우드 모두 지원한다. [오픈소스 에디션](https://github.com/langgenius/dify)은 워크플로 빌더, RAG 엔진, 에이전트 기능, API 생성, 멀티유저 워크스페이스 등 핵심 기능 전체를 포함하며, 비용은 하드웨어·전기료 외에 별도 라이선스 비용이 없다.

---

## 준비물

### 하드웨어

[공식 문서](https://docs.dify.ai/en/self-host/deploy/quick-start/docker-compose)에 명시된 최소 사양은 **CPU 2코어, RAM 4 GiB**다. 모델 추론을 외부 API에 맡기는 경우 Dify Docker 스택(API 서버·워커·PostgreSQL·Redis·Weaviate·Nginx)의 유휴 메모리 사용량은 약 2.5 GB다. Ollama로 로컬 추론을 함께 돌릴 계획이라면 모델 크기에 따라 8 GiB 이상을 준비하는 것이 좋다.

### 소프트웨어

[공식 문서](https://docs.dify.ai/en/self-host/deploy/quick-start/docker-compose)에 따르면 Docker와 **Docker Compose 2.35.0 이상**이 필요하며, 저장소 클론에 Git, 에이전트 로컬 샌드박스 토큰 생성에 OpenSSL도 필요하다.

### 모델 / API 키

Settings → Model Provider에서 OpenAI 또는 Anthropic API 키를 추가하면 Dify가 사용 가능한 모델 목록을 자동으로 불러온다. 비용 없이 로컬 추론을 원한다면 Ollama를 설치하고 Dify 설정에서 Ollama 엔드포인트를 지정하면 된다.

## 설치: Docker Compose로 3단계

### 1단계 — 저장소 클론 및 환경 설정

```bash
git clone https://github.com/langgenius/dify.git
cd dify/docker
cp .env.example .env
openssl rand -hex 32
# 출력값을 .env의 DIFY_AGENT_LOCAL_SANDBOX_AUTH_TOKEN에 붙여넣기
```

[공식 문서](https://docs.dify.ai/en/self-host/deploy/quick-start/docker-compose)는 벡터 스토어(기본 Weaviate)나 데이터베이스(기본 PostgreSQL)를 변경하려면 **첫 시작 전**에 `.env`에서 설정해야 한다고 명시한다. 첫 시작 후 전환하면 기존 데이터가 이전되지 않는다.

### 2단계 — 서비스 기동

```bash
docker compose up -d
docker compose ps --all   # 모든 서비스 상태 확인
```

Postgres, Redis, Weaviate, API 서버, 웹 UI가 모두 올라온다. 첫 실행 시 이미지 풀링 포함 약 2~3분이 소요된다.

### 3단계 — 관리자 계정 설정

브라우저에서 `http://localhost/install`로 이동해 관리자 이메일과 비밀번호를 설정하면 Dify 대시보드에 접속된다.

## 핵심 기능 3가지 실전 활용

### 1. RAG 챗봇 — 내 문서에 질문하기

[공식 문서](https://docs.dify.ai/en/self-host/deploy/quick-start/docker-compose)에 따르면 지식 베이스에 업로드할 수 있는 형식은 **PDF, Markdown, TXT, HTML, DOCX, CSV**다. 업로드된 문서는 Weaviate 벡터 DB에 임베딩되어 저장된다.

워크플로 노드 구성 흐름:

| 노드 | 역할 |
|---|---|
| **Start** | 사용자 입력 수신 |
| **Knowledge Retrieval** | 벡터 유사도(RAG)로 지식 베이스 검색 |
| **LLM** | 검색 결과를 컨텍스트로 답변 생성 |
| **Answer** | 최종 출력 반환 |

Publish 버튼을 누르면 앱이 REST API 엔드포인트와 공유 가능한 채팅 URL을 즉시 얻는다. 사내 문서 Q&A, 고객 지원 봇 등을 별도 백엔드 개발 없이 만들 수 있다는 것이 핵심이다.

### 2. AI 워크플로 — 다단계 자동화 파이프라인

[Dify 공식 GitHub](https://github.com/langgenius/dify)에 따르면 워크플로는 LLM·데이터베이스·API·코드를 드래그앤드롭 캔버스에서 연결하는 비주얼 노드 기반 AI 파이프라인이다. 주요 노드 유형은 다음과 같다.

- **Code 노드**: Python 또는 JavaScript를 워크플로 내에서 직접 실행
- **HTTP Request 노드**: 외부 REST API 호출
- **If/Else 노드**: 문자열 비교·수치 임계값·정규식 매칭으로 분기

게시된 모든 워크플로는 `POST https://your-dify-instance/v1/workflows/run` REST API 엔드포인트를 자동으로 얻는다. 이 엔드포인트를 Webhook이나 외부 앱과 연결하면 자체 오케스트레이션 레이어 없이도 복잡한 AI 파이프라인을 운영할 수 있다.

### 3. Dify Agent — 명령·파일 실행 에이전트 (v1.16.0+)

[GitHub 릴리스 1.16.0](https://github.com/langgenius/dify/releases/tag/1.16.0)에 따르면 기존 에이전트가 등록된 도구를 호출하는 방식이었다면, v1.16.0부터 추가된 새 Agent App은 격리된 환경 안에서 명령을 실행하고 파일을 직접 생성한다. 포함된 구성 요소는 다음과 같다.

- **내장 샌드박스**: 코드 실행과 셸 명령 격리
- **Skill 시스템**: 도구와 API를 인라인으로 호출
- **에이전트 목록**: 워크스페이스 전반에서 에이전트를 관리·재사용

> ⚠️ **주의**: [공식 릴리스 노트](https://github.com/langgenius/dify/releases/tag/1.16.0)에 따르면 Agent App은 현재 **Open Beta** 단계다. 프로덕션 환경에서는 릴리스 노트를 확인하며 버전을 고정할 것을 권장한다.

## Dify 1.19.0 주요 변경 (2026-11-04 출시)

[openorchestrators.org 릴리스 정리](https://openorchestrators.org/news/dify-1-19-0-nested-tracing-portable-workflow-tools/)에 따르면 1.19.0의 핵심 변경 사항은 세 가지다.

1. **중첩 Workflow Tool 트레이싱**: 외부 트레이스에 Workflow Tool이 호출한 내부 실행 단계가 포함되어, 중첩·반복 호출 전반에 걸쳐 계층 구조가 유지된다. 복잡한 에이전트 디버깅이 훨씬 수월해진다.
2. **이식 가능한 Workflow Tool 패키지**: 내보낸 `.ifpkg` 파일에 호출된 Workflow Tool의 바운드 버전이 포함(기본 최대 20개)된다. 임포트 시 목적지 워크스페이스에 이미 있는 도구는 재사용하고, 없는 것은 재생성·게시·등록한다.
3. **배치 Agent 파일 업로드**: 에이전트에 파일을 일괄로 업로드할 수 있게 됐다.

## 비용 및 제약 요약

| 항목 | 내용 |
|---|---|
| 오픈소스 에디션 | Apache 2.0, 무료 셀프호스트, 크레딧 제한 없음 |

| 로컬 모델 사용 | Ollama 연동 시 모델 크기에 따라 8 GiB 이상 |
| 벡터 스토어 변경 | 첫 시작 전에만 가능 |
| 백업 필수 항목 | PostgreSQL 덤프(`pg_dump`), Docker 볼륨, `.env` 파일 |

## 마치며

Dify는 "LLM 앱 스택 전체를 직접 운영하고 싶지만 각 부품을 하나씩 연결하기 싫다"는 개발자와 크리에이터에게 현실적인 선택지다. 셀프호스트 에디션은 Apache 2.0으로 무료이며, Docker Compose 세 단계면 RAG 챗봇부터 다단계 AI 파이프라인, 파일 실행 에이전트까지 한 대시보드에서 관리할 수 있다.

단, Agent App이 아직 Open Beta임을 명심하고 프로덕션 도입 전 [릴리스 노트](https://github.com/langgenius/dify/releases)를 꼭 확인하길 권한다.
