## 무엇을 해결하는가

Claude Code나 Codex 같은 CLI 코딩 에이전트는 대부분 사람이 터미널 앞에 앉아 있는 동안에만 동작합니다. 창을 닫으면 작업이 멈추고, 다음 작업을 시키려면 다시 돌아와야 합니다.

[agent-autoloop README](https://github.com/KKKKhazix/agent-autoloop/blob/main/README.en.md)에 따르면, 이 도구는 그 문제를 풀기 위한 "극경량 자동화 허브"입니다. 에이전트가 스스로 작업을 이어가다가 판단이 필요한 순간에만 카드(알림)를 보내 사용자에게 확인을 요청하는 구조입니다. 별도 서버를 구매하지 않아도 되고, 공인 IP를 열지 않아도 Mac·Linux·Windows 위에서 실행됩니다.

---

## 아키텍처: 커널 + 플러그인

[README](https://github.com/KKKKhazix/agent-autoloop)에 명시된 구조는 크게 두 층으로 나뉩니다.

**커널**은 약 1,650~1,850행의 TypeScript 코드로, 외부 런타임 의존성이 없습니다. 시스템 클럭을 직접 읽지 않고 외부 요청도 보내지 않으며, 플러그인이 먼저 커널에 접속하는 단방향 구조라 같은 입력에는 항상 같은 결과가 나옵니다.

**플러그인**은 네 방향으로 구성됩니다.

| 방향 | 지원 목록 |
|---|---|
| 이벤트 소스 | GitHub Webhook, HTTP 인터페이스, 정시 규칙, Issue 폴링 |
| 에이전트 | Claude Code, Codex, ACP, 범용 CLI |
| 알림 채널 | 데스크톱 알림(기본), 飛書(Feishu), 钉钉·企微·Slack·Discord |
| 딜리버리 | CI/CD 파이프라인 연결 |

에이전트가 사용자에게 질문할 때 agent-autoloop 블록이 대화에 추가되고, 사용자가 3일 뒤에 답해도 그사이 에이전트 프로세스는 실행되지 않습니다. 답변이 오면 원래 대화가 재개됩니다.

## 설치 및 주요 명령어

### 설치 (macOS/Linux)

[README](https://github.com/KKKKhazix/agent-autoloop/blob/main/README.en.md)에 명시된 방법입니다. Node 24, Git, curl이 사전 설치되어 있어야 합니다.

```bash
curl -fsSL https://raw.githubusercontent.com/KKKKhazix/agent-autoloop/main/install.sh | bash
```

### 상태 확인 명령어

README에 기재된 CLI 명령입니다.

```bash
agent-autoloop check              # 설정 유효성 검사
agent-autoloop rules explain      # 활성 규칙과 다음 실행 시각 확인
agent-autoloop emit <type> --dry-run  # 이벤트 라우팅 미리 보기 (허브 미접속)
agent-autoloop run <rule>         # 규칙 즉시 1회 실행
```

설정을 잘못 고쳐도 파일이 삭제되거나 읽히지 않으면 시스템은 이전 규칙으로 계속 동작하고, 카드로 사용자에게 알립니다.

## 구체적 예제: GitHub Issue 추적 패턴

[README 기재 템플릿](https://github.com/KKKKhazix/agent-autoloop)을 기반으로 한 구성 예시입니다. 5분마다 신규 Issue를 확인하고, 로컬 코드 수정 후 사용자에게 확인을 요청합니다(커밋·푸시·Issue 댓글은 자동으로 하지 않습니다).

```jsonc
// ~/.agent-autoloop/rules.json (README 기재 패턴)
{
  "rules": [
    {
      "name": "issue-watcher",
      "event": "github-issue",
      "agent": "claude-code",
      "cwd": "~/projects/myapp",
      "interval": "5m"
    }
  ]
}
```

README에는 이 외에도 네 가지 시나리오 템플릿이 더 제공됩니다.

- **일일 브리핑**: 매일 오전 8시 로컬 노트·Git 커밋 정리 → `briefs/YYYY-MM-DD.md` 저장
- **온라인 알람 분석**: 에러 수신 → 코드 대조 → 재시작 필요 시 카드 발송
- **웹사이트 모니터링**: 5분마다 상태·콘텐츠 점검 → 이상 감지 시 에이전트 개입
- **PR 자동 딜리버리**: `deliver` 태그 → 리뷰·CI 대기·머지·배포 확인

## 검증 범위와 한계

[README](https://github.com/KKKKhazix/agent-autoloop/blob/main/README.en.md)에 명시된 검증 범위입니다.

**통과 항목**: Claude Code, Codex, ACP의 다중 라운드 대화 및 크로스 프로세스 세션 재개. 飛書의 발송·버튼 콜백·카드 업데이트.

**미완료 항목**: 4종 Webhook 템플릿은 로컬 모의 서버에서만 검증되었으며, Slack·Discord·钉钉·企微 등 일부 텍스트 채널은 실제 계정 엔드투엔드 테스트가 완료되지 않았습니다.

추가로 현 시점에서 불확실한 부분도 있습니다.

1. **저자 정보**: KKKKhazix 외 추가 메인테이너 여부·소속 미확인.
2. **스타 급상승 원인**: 공개 직후 단기 급증이 유기적 관심인지 소셜 증폭인지 현재로서는 구분 불가.
3. **장기 유지보수**: 개인 개발자 프로젝트이므로 지속적 유지보수 여부는 미지수.

## 정리

agent-autoloop는 "에이전트를 계속 켜두고 싶다"는 단순하지만 실질적인 문제를 커널·플러그인 분리 방식으로 접근한 프로젝트입니다. 커널이 외부 의존성 없이 결정론적으로 동작하고, 에이전트·채널·CI를 모두 플러그인으로 분리한 설계는 장기적인 확장성을 고려한 선택처럼 보입니다. 다만 채널 일부의 실계정 테스트가 미완료 상태이고 개인 프로젝트라는 점은 프로덕션 도입 전에 고려해야 할 요소입니다.
